## 🔴 Kritik Güvenlik Açıkları

### 🔴-1: Firebase Rules Açık (ÇOK KRİTİK)
**Bulgu:** auth.js ve firebase-sync.js, Firebase Realtime Database'e şu formatla erişiyor:
```
https://tustakip-default-rtdb.europe-west1.firebasedatabase.app/tus_v4/auth.json
```
Firebase Rules "public" ya da "read: true" ise herhangi biri curl ile tüm şifre hashlerini,
tüm kullanıcıların verilerini çekebilir. Kodda herhangi bir auth token veya Firebase Auth SDK kullanılmıyor.

**Risk:** Birisi tustakip-default-rtdb.europe-west1.firebasedatabase.app/tus_v4.json adresini açarsa
İlay'ın 1.096 sayfalık çalışma geçmişi, şifre hash'leri ve partner notu herkese açık olabilir.

**Öneri (Firebase Console → Realtime Database → Rules):**
```json
{
  "rules": {
    ".read": false,
    ".write": false
  }
}
```
Kısa vadede bu kural en azından false yapılmalı.
Orta vadede Firebase Authentication + Custom Token altyapısına geçilmeli.

---

### 🔴-2: HASH_SALT Koda Gömülü (Orta Kritik)
**Bulgu:** auth.js satır 7:
```js
const HASH_SALT = 'tus_takip_salt_2026';
```
Bu salt kaynak kodunda herkesin görebileceği yerde. Repo public olduğunda saldırgan bu salt'ı alıp
rainbow table ile hash'leri kırabilir.

**Öneri:** Salt her kullanıcıya özel (ör. username + createdAt) olmalı
ya da Firebase Authentication'a geçilmeli.

---

### 🔴-3: backup_ilay_data_v3.json ve current_firebase_data.json Git'te
**Bulgu:** Bu dosyalar .gitignore'da değil. İçlerinde İlay'ın tüm çalışma kayıtları (tarihler, sayfa sayıları),
partner notu ve ayarlar var. Bir git push ile GitHub'a çıkar, herkes görebilir.

**Öneri - .gitignore'a ekle:**
```
backup_*.json
current_firebase_data.json
```
Ve bu dosyaları git geçmişinden temizle (git rm --cached).

### 🟡-2: Quiz Soru Yükleme Mekanizması Kırık
**Bulgu:** quiz.js → eski yol fallback olarak hâlâ kodda duruyor. Manifest 13 branşı destekliyor
ama quiz motoru sadece questions_fizyoloji.json dosyasını yüklüyor.
İkinci kitap eklense bile quiz bunu görmez.

**Öneri:** Manifest'ten tüm aktif branşların JSON'larını dinamik yükleyen loadAllQuestions() fonksiyonu yazılmalı.
FALLBACK_QUESTIONS kaldırılmalı.

---

### 🟡-3: setInterval(updateExamCountdown, 1000) İki Kez Çağrılıyor
**Bulgu:** app.js:
- Satır 1255: init() içinde
- Satır 1275: startPeriodicSync() içinde

Her giriş yapıldığında 2 paralel interval başlıyor. Uzun süre açık kalan sekmede onlarca
interval birikir, performansı yer.

**Öneri:** init()'teki interval kaldırılmalı, sadece startPeriodicSync() içinde bırakılmalı.

---

### 🟡-4: firebase-sync.js → activeUser: 'ilay' Default
**Bulgu:** firebase-sync.js satır 30:
```js
activeUser: 'ilay',
```
setTargetUser() çağrılmadan fetchAll() veya saveAll() çağrılırsa her zaman İlay'ın datasına yazar.
Race condition durumunda başka kullanıcının verisi İlay'a gidebilir.

**Öneri:** Default null yapılmalı, null ise hata fırlatılmalı.

---

### 🟡-5: entries.indexOf() Referans Hatası
**Bulgu:** app.js satır 384:
```js
c.innerHTML = sorted.map(e => createEntryHTML(e, entries.indexOf(e))).join('');
```
sorted = entries'in filtrelenmiş + sıralanmış kopyası. entries.indexOf(e) nesne referansı karşılaştırır;
kopyalama veya JSON.parse sonrasında aynı obje olmayabilir → yanlış indeks → delete yanlış kaydı siler.

**Öneri:** Entry'lere id alanı eklenmeli, indeks yerine id ile işlem yapılmalı.
